1. VISIÓN GENERAL Y ARQUITECTURA DEL SISTEMA
================================================================================

1.1. Propósito del Sistema
SenaAccess es una solución integral diseñada para modernizar y asegurar el control
de flujo peatonal, la trazabilidad de equipos de cómputo y la gestión de novedades en
los ambientes del SENA. Reemplaza los registros en papel mediante una arquitectura
digital que combina credenciales seguras, carnets digitales con códigos QR de alta densidad,
asistente virtual con Inteligencia Artificial (Gemini) y validación biométrica dactilar.

1.2. Principio Arquitectónico: Desacoplamiento API-First
El sistema implementa una arquitectura desacoplada estructurada en tres capas principales:

1. Frontend (SPA - Single Page Application):
   Interfaz de usuario moderna construida en React 19 con enrutamiento de cliente
   (React Router 7) y empaquetador de módulos Vite. La aplicación se ejecuta
   íntegramente en el navegador sin recargas de página (full page reload).
   Incorpora un diseño visual ciber-minimalista con efectos Glassmorphism (clases
   glass-box, btn-glow, neon-text) y Bootstrap 5.3 para adaptabilidad responsiva.
   Integra directamente captura de hardware (cámara web para escaneo QR con html5-qrcode
   y renderizado de carnets con qrcode y html2canvas).

2. Backend Principal (API Gateway - Laravel 10 / PHP 8.2+):
   Núcleo transaccional y de lógica de negocio. Opera como una API RESTful stateless.
   Gestiona la seguridad y autenticación mediante Laravel Sanctum (tokens Bearer),
   aplica el control de acceso basado en roles (RBAC), manipula la persistencia
   en la base de datos relacional MySQL y orquesta servicios externos en la nube
   (Cloudinary, Google Gemini AI, Resend).

3. Microservicio Biométrico (Python / Flask):
   Servicio aislado y especializado para el procesamiento matemático y visual de
   huellas dactilares. Al desacoplar el procesamiento intensivo de imágenes a un entorno
   Python con OpenCV y NumPy (algoritmo ORB), se evitan bloqueos en los procesos PHP
   y se garantiza alta velocidad de respuesta con aislamiento de fallos.

1.3. Matriz de Roles del Sistema (RBAC)
- Administrador (admin): Control total de usuarios, roles, comprobantes de equipos,
  auditoría de ingresos globales y administración de novedades.
- Instructor (instructor): Consulta de ingresos de aprendices, reporte y seguimiento
  de novedades en ambientes de formación y control de sus propios equipos.
- Aprendiz (aprendiz): Consulta de historial personal de ingresos, generación y
  descarga de su Carnet Digital QR y actualización de perfil personal.
- Funcionario (funcionario): Registro institucional de acceso y vinculación de equipos
  corporativos asignados.
- Invitado (invitado): Registro ágil de visitantes ocasionales mediante documento
  de identidad para control de ingreso temporal.

2. REQUISITOS DEL SISTEMA E INFRAESTRUCTURA
================================================================================

2.1. Requisitos de Software - Backend y Base de Datos
- PHP: Versión 8.2.0 o superior (compatible con PHP 8.3).
  Extensiones obligatorias: pdo_mysql, openssl, mbstring, tokenizer, xml, ctype,
  json, curl, fileinfo, gd, bcmath.
- Composer: Versión 2.5.0 o superior.
- Motor de Base de Datos: MySQL 8.0+ o MariaDB 10.4+ (motor InnoDB, charset utf8mb4).
- Servidor Web: Nginx 1.22+, Apache 2.4+ (con mod_rewrite) o php artisan serve.

2.2. Requisitos de Software - Frontend
- Node.js: Versión 18.18.0 LTS o 20.x LTS.
- npm: Versión 9.x o superior.
- Vite: Versión 6.0 o superior.

2.3. Requisitos de Software - Microservicio Biométrico (Python)
- Python: 3.9 a 3.12.
- Dependencias: Flask >= 3.0.0, opencv-python-headless >= 4.9.0, numpy >= 1.26.0,
  gunicorn >= 21.2.0 (producción).

2.4. Hardware Mínimo Recomendado
- Entorno Local: CPU 2 núcleos, 4 GB RAM, 5 GB de espacio en disco.
- Servidor Cloud / Producción: 2 vCPUs dedicados, 2 GB a 4 GB RAM (Swap de 2 GB),
  20 GB SSD NVMe.
- Dispositivo Cliente: Navegador moderno (Chrome, Edge, Firefox) con acceso a cámara web.

3. COMANDOS DE DESPLIEGUE Y PUESTA EN MARCHA
================================================================================

3.1. Despliegue en Entorno Local (Windows / Linux / macOS)

Paso 1: Clonar el repositorio y acceder a la carpeta:
  git clone https://github.com/ShyD0s/SenaAccessFinal.git
  cd SenaAccessFinal

Paso 2: Instalación de dependencias:
  composer install
  npm install

Paso 3: Configurar variables de entorno y generar Application Key:
  # En Windows:
  copy documentacion\env-ejemplo.txt .env
  # En Linux/macOS:
  cp documentacion/env-ejemplo.txt .env

  # Generar clave de cifrado:
  php artisan key:generate

Paso 4: Configurar Base de Datos en .env:
  DB_CONNECTION=mysql
  DB_HOST=127.0.0.1
  DB_PORT=3306
  DB_DATABASE=senaaccess
  DB_USERNAME=root
  DB_PASSWORD=

Paso 5: Ejecutar migraciones y datos semilla (Seeders):
  # Asegurarse de tener el servicio MySQL iniciado (ej: XAMPP)
  php artisan migrate:fresh --seed

  Credenciales predeterminadas generadas por el Seeder:
  * Admin:       admin@sena.edu.co       | Clave: senaaccess
  * Instructor:  instructor@sena.edu.co  | Clave: senaaccess
  * Aprendiz:    maria@sena.edu.co       | Clave: senaaccess
  * Funcionario: funcionario@sena.edu.co | Clave: senaaccess

Paso 6: Enlazar almacenamiento de archivos (si aplica):
  php artisan storage:link

Paso 7: Iniciar los servidores de desarrollo en dos terminales:
  Terminal 1 (Backend):  php artisan serve --port=8000
  Terminal 2 (Frontend): npm run dev

  Abrir en el navegador: http://localhost:8000


3.2. Despliegue en Entorno de Producción (Cloud / VPS / Railway)

1. Instalación de dependencias de producción:
   composer install --no-dev --optimize-autoloader

2. Compilación de la aplicación React con Vite:
   npm run build

3. Cacheado y optimización de Laravel:
   php artisan config:cache
   php artisan route:cache
   php artisan view:cache

4. Ejecución de migraciones en producción:
   php artisan migrate --force

5. Permisos de carpetas en servidores Linux:
   chmod -R 775 storage bootstrap/cache
   chown -R www-data:www-data storage bootstrap/cache

5. ESPECIFICACIÓN DE ENDPOINTS PRINCIPALES (REST API)
================================================================================

Formato general:
- Todas las peticiones reciben y devuelven application/json (excepto cargas multimedia multipart/form-data).
- Las rutas protegidas exigen el encabezado: Authorization: Bearer <access_token>

5.1. Autenticación y Cuentas
- POST /api/register
  Descripción: Registra un nuevo usuario tipo aprendiz o funcionario.
  Público | Body JSON: user_identification, user_name, user_lastname, user_email,
  user_password, user_password_confirmation, user_coursenumber, user_program, role.
  Respuestas: 201 Created (retorna usuario creado), 422 Unprocessable Content.

- POST /api/login
  Descripción: Autentica al usuario, inserta un registro en la tabla 'ingresos'
  con fecha y hora de Bogotá y retorna el Bearer Token de Sanctum.
  Público | Body JSON: user_email, user_password.
  Respuestas: 200 OK (retorna user, role, access_token), 401 Unauthorized.

- POST /api/register-guest
  Descripción: Registra el ingreso de un visitante externo temporal.
  Público | Body JSON: user_identification, user_name.
  Respuestas: 201 Created.

- POST /api/forgot-password
  Descripción: Genera un token alfanumérico aleatorio de 8 caracteres en 'token_recovery'
  con validez de 15 minutos y envía un correo transaccional vía Resend.
  Público | Body JSON: email.
  Respuestas: 200 OK.

- POST /api/reset-password
  Descripción: Valida el código de 8 caracteres y actualiza la contraseña del usuario.
  Público | Body JSON: code, password, password_confirmation.
  Respuestas: 200 OK, 400 Bad Request (código inválido o expirado).

- POST /api/logout
  Descripción: Elimina el token actual en la base de datos de Sanctum.
  Protegido (auth:sanctum) | Respuestas: 200 OK.

- GET /api/user
  Descripción: Obtiene los datos del usuario logueado con su relación de rol cargada.
  Protegido (auth:sanctum) | Respuestas: 200 OK.

5.2. Gestión de Usuarios y Perfiles
- GET /api/admin/users
  Descripción: Lista todos los usuarios con sus roles y comprobantes de equipos.
  Protegido (auth:sanctum + admin_or_instructor) | Respuestas: 200 OK.

- POST /api/admin/users
  Descripción: Crea un nuevo usuario desde el panel de administración.
  Soporta carga de avatar para Cloudinary en multipart/form-data (campo 'image').
  Protegido (auth:sanctum + admin) | Respuestas: 201 Created, 422 Unprocessable.

- PUT /api/admin/users/{id}
  Descripción: Actualiza la información y/o imagen de un usuario específico.
  Protegido (auth:sanctum + admin) | Respuestas: 200 OK.

- DELETE /api/admin/users/{id}
  Descripción: Elimina a un usuario del sistema.
  Protegido (auth:sanctum + admin) | Respuestas: 200 OK.

- PUT /api/my-profile
  Descripción: Actualiza los datos personales y la foto de carnet del usuario en sesión.
  Sube la nueva foto a Cloudinary y guarda la URL en 'profile_photo_path'.
  Protegido (auth:sanctum) | Respuestas: 200 OK.

5.3. Gestión de Comprobantes de Equipos
- POST /api/admin/equipment
  Descripción: Registra el comprobante de ingreso de un portátil o equipo de cómputo.
  Protegido (auth:sanctum + admin) | Body JSON: fk_id_usuario, equipo_type, equipo_brand,
  equipo_model, equipo_color, equipo_serial, equipo_observations.
  Respuestas: 201 Created.

- GET /api/admin/equipment
  Descripción: Lista todos los comprobantes de ingreso de equipos ordenados por fecha.
  Protegido (auth:sanctum + admin) | Respuestas: 200 OK.

- GET /api/my-equipment
  Descripción: Lista los comprobantes de equipos pertenecientes al usuario actual.
  Protegido (auth:sanctum) | Respuestas: 200 OK.

- DELETE /api/admin/equipment/{id}
  Descripción: Da de baja un registro de equipo.
  Protegido (auth:sanctum + admin) | Respuestas: 200 OK.

5.4. Gestión de Novedades de Ambientes
- GET /api/novedades
  Descripción: Lista de novedades reportadas en la sede. Soporta filtro '?search='.
  Protegido (auth:sanctum + admin_or_instructor) | Respuestas: 200 OK.

- POST /api/novedades
  Descripción: Registra un nuevo incidente o novedad de ambiente.
  Protegido (auth:sanctum + admin_or_instructor) | Body JSON: novedad_ambiente,
  novedad_title, novedad_body.
  Respuestas: 201 Created.

- PUT /api/novedades/{id}
  Descripción: Modifica una novedad. Solo permitida para su autor original o admin.
  Protegido (auth:sanctum + admin_or_instructor) | Respuestas: 200 OK, 403 Forbidden.

- DELETE /api/novedades/{id}
  Descripción: Elimina una novedad. Solo permitida para su autor original o admin.
  Protegido (auth:sanctum + admin_or_instructor) | Respuestas: 200 OK, 403 Forbidden.

5.5. Inteligencia Artificial (Chatbot)
- POST /api/chatbot
  Descripción: Procesa consultas de usuarios con contexto institucional usando Gemini AI.
  Protegido (auth:sanctum) | Body JSON:
  {
    "message": "¿Cómo descargo mi carnet QR?",
    "history": [{"role": "user", "text": "..."}, {"role": "model", "text": "..."}]
  }
  Respuestas: 200 OK ({"reply": "..."}), 422 Unprocessable, 502 Bad Gateway.

6. CONFIGURACIÓN Y CONTROLADORES DE SERVICIOS EXTERNOS
================================================================================

6.1. CLOUDINARY (Almacenamiento CDN de Fotos de Perfil)
Propósito: Persistir de forma segura y optimizada en la nube las fotos de perfil
de aprendices e instructores, evitando almacenamiento local y permitiendo que los
carnets digitales se sirvan en URLs HTTPS ultrarrápidas con CDN.

- Variables en .env:
  CLOUDINARY_URL=cloudinary://<API_KEY>:<API_SECRET>@<CLOUD_NAME>
  CLOUDINARY_UPLOAD_PRESET=senaacess

- Paquete Laravel utilizado: cloudinary-labs/cloudinary-laravel (^2.3)
- Controlador responsable: UserController.php
  Implementación en métodos createUser, updateUser y updateMyProfile:
  ```php
  if ($request->hasFile('image')) {
      $profile_photo_path = $request->file('image')
          ->storeOnCloudinary('avatars')
          ->getSecurePath();
      $user->profile_photo_path = $profile_photo_path;
  }
  ```
- Consumo en Frontend:
  La URL de Cloudinary se renderiza en 'UserQrCarnet.jsx' y los dashboards de
  Admin y Aprendiz para exhibir la fotografía oficial en el Carnet Digital.


6.2. GOOGLE GEMINI AI (Chatbot de Asistencia Institucional)
Propósito: Asistente virtual automatizado para resolver dudas sobre acceso al SENA,
uso del carnet QR, registro de equipos y recuperación de contraseñas.

- Variable en .env:
  GEMINI_API_KEY=AIzaSy...TuClaveGoogleAIStudio...

- Configuración en config/services.php:
  'gemini' => [
      'api_key' => env('GEMINI_API_KEY'),
  ],

- Controlador responsable: ChatbotController.php
  Estrategia de Resiliencia:
  1. Failover de modelos: Se intenta primero con 'gemini-3.8-flash' (modelo principal
     de alto rendimiento) y si la cuota o disponibilidad falla, conmuta automáticamente
     a 'gemini-3.5-flash-lite' (respaldo de baja latencia con cuota separada).
  2. Reintentos automáticos: Se ejecutan hasta 3 reintentos separados por 500ms
     ante errores 5xx del servidor de Google (Http::timeout(20)->retry(3, 500)).
  3. Prompt de Sistema (System Instruction): Instruye al modelo para actuar
     estrictamente como asistente de SenaAccess, responder siempre en español,
     no revelar secretos o contraseñas, no usar emojis y estructurar con Markdown.


6.3. RESEND / SERVICIO DE CORREO TRANSACCIONAL
Propósito: Envío seguro de correos electrónicos para el proceso de recuperación de
contraseñas olvidadas con códigos de verificación temporales.

- Variables en .env:
  MAIL_MAILER=resend
  RESEND_API_KEY=re_AF3A8QCP_MoWy742jPXsnG2ySH4RRZFqE
  MAIL_FROM_ADDRESS="onboarding@resend.dev"
  MAIL_FROM_NAME="SENA Access"

- Paquete Laravel: resend/resend-laravel (^1.3)
- Clase Mailable: app/Mail/RecoveryCodeMail.php
- Controlador responsable: AuthController.php (forgotPassword)
  Genera un token de 8 caracteres en 'token_recovery' con 15 minutos de validez y
  despacha el email:
  ```php
  Mail::to($user->user_email)->send(new \App\Mail\RecoveryCodeMail($token));
  ```


6.4. MICROSERVICIO BIOMÉTRICO (Python + OpenCV + ORB)
Propósito: Procesamiento y cotejo computacional de huellas dactilares sin sobrecargar
el servidor PHP de Laravel.

- Tecnologías: Python 3.9+, Flask, OpenCV, NumPy.
- Flujo:
  1. React captura la imagen de la huella y la envía a Laravel.
  2. Laravel valida la sesión y reenvía internamente la imagen al microservicio Flask.
  3. Flask aplica ecualización de histograma adaptativa (CLAHE), extrae los
     descriptores de puntos clave con el algoritmo ORB y calcula la similitud vectorial.
  4. Si la coincidencia supera el umbral del 75%, retorna verificación positiva a Laravel.
  5. Laravel registra el ingreso en la base de datos MySQL y confirma al cliente.

================================================================================
8. SEGURIDAD Y MANTENIMIENTO
================================================================================

1. Almacenamiento seguro de contraseñas mediante Hash::make() con Bcrypt.
2. Inyección de variables de entorno para todas las credenciales externas sensibles.
3. Control de acceso granular en backend con middleware específico por rol.
4. Expiración estricta de tokens de recuperación (15 minutos) y marcado de un solo uso.
5. Invalidador de sesión y tokens de Sanctum en cada logout explícito.
